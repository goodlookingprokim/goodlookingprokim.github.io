# BananaX를 그냥 프롬프트 모음으로 보면 아깝다: 초보자도 바로 써먹는 인포그래픽 활용 허브

AI로 카드뉴스나 인포그래픽을 만들다 보면 금방 비슷한 벽을 만난다. “뭘 넣어야 예뻐지지?”보다 더 자주 막히는 건, **어느 스타일을 골라야 하는지 모르겠고, 만든 결과가 괜찮은지도 판단하기 어렵다**는 점이다.

이번에 `https://furoku.github.io/bananaX/`를 깊게 읽어보니, 이 사이트는 단순히 예쁜 프롬프트를 모아둔 곳이 아니었다. 오히려 더 중요한 건, 초보자가 헤매는 순서를 꽤 잘 알고 있다는 점이었다. 스타일을 고르는 메인 허브, 실제 사례를 보는 갤러리, 업무와 학습용 프롬프트 라이브러리, 특집형 아카이브까지 나눠두어서 “어디서부터 시작해야 하지?”를 덜 묻게 만든다.

## 먼저 결론

- BananaX의 진짜 강점은 프롬프트 한 줄보다 **용도별로 나뉜 4개 사이트 구조**에 있다.
- 처음 쓰는 사람은 메인 허브에서 스타일을 고르고, 사례 갤러리에서 결과 감각을 익히고, BananaPrompt에서 문장 재료를 보강하는 순서가 가장 덜 헤맨다.
- 이 도구는 “AI가 다 만들어준다”보다 **사람이 빠르게 선택하고 비교하고 수정하게 도와주는 안내판**에 가깝다.

## BananaX를 먼저 볼 만한 이유

BananaX 공식 디렉터리는 전체를 아예 4개 사이트로 나눠서 보여준다.

- `Main Hub`: 300개가 넘는 인포그래픽 프롬프트 스타일을 검색, 비교, 복사하는 메인 사이트
- `Research`: DeNA `AI 100 Knocks`를 인포그래픽 사례로 다시 보는 갤러리
- `Library`: 업무와 학습에 쓸 수 있는 `AI 프롬프트 1000` 라이브러리
- `Archive`: 겨울 올림픽 테마로 묶인 디자인 평가 아카이브

이 구조가 중요한 이유는, 초보자가 실제로 겪는 문제를 순서대로 나눠주기 때문이다.

- 지금 나는 스타일이 필요한가
- 좋은 결과 예시가 필요한가
- 문장 재료가 필요한가
- 특정 주제의 비교 아카이브가 필요한가

이걸 한 화면에서 고르게 해주니, “사이트는 멋진데 어디를 눌러야 할지 모르겠다”는 느낌이 덜하다.

## BananaX를 쉽게 쓰는 가장 현실적인 순서

처음부터 기능을 다 보려고 하면 오히려 산만하다. 가장 쉬운 흐름은 이 순서다.

### 1) 메인 허브에서 스타일 감을 먼저 잡는다

메인 허브의 핵심 문구는 단순하다.

- `스타일 선택`
- `카드 열기`
- `복사`

이 3탭 동선이 꽤 좋다. 처음부터 프롬프트를 공부하게 만들지 않고, 먼저 “내가 원하는 그림 톤”을 고르게 한다. 특히 `NotebookLM / Gemini / ChatGPT / Grok`에서 쓸 수 있는 예시라는 점을 앞에 걸어둔 것도 실전적이다.

즉 이 단계의 목표는 완성본을 뽑는 게 아니라, **내가 원하는 시각 언어를 빨리 고르는 것**이다.

### 2) 사례 갤러리에서 결과물의 밀도를 익힌다

`AI Use Case Gallery`는 DeNA의 AI 활용 사례를 인포그래픽처럼 다시 보여주는 실험형 갤러리다. 여기서 좋은 건 단순 예시 이미지가 아니라,

- `Challenge & Background`
- `Results & Impact`
- `View PDF Materials`

같이 결과물의 정보 구조를 함께 보여준다는 점이다.

그리고 더 흥미로운 건 요약을 여러 말투로 다시 뽑는 `AI Summary Generator`다.

- `2ch Style`
- `JK Style`
- `Consultant Style`

이런 건 장난 같아 보여도 실제로는 꽤 쓸모가 있다. 같은 내용을 다른 말투와 톤으로 바꿔보면, **자료의 핵심은 유지하면서 전달 방식만 바꿀 수 있는지** 감을 익히게 해주기 때문이다.

### 3) BananaPrompt에서 문장 재료를 보충한다

BananaX 메인 쪽이 스타일 사전이라면, `BananaPrompt`는 문장 재료 창고에 가깝다.

공개된 구조를 보면 `ALL / 仕事 / 勉強` 식으로 나뉘어 있고, 설명과 함께 프롬프트를 복사할 수 있다. 이건 특히 아래 같은 상황에서 쓸모가 크다.

- 카드뉴스 주제는 정했는데 문장이 심심할 때
- 설명 순서를 어떻게 잡아야 할지 막힐 때
- 업무용 문장과 학습용 문장을 분리해서 보고 싶을 때

즉 BananaPrompt는 메인 허브의 경쟁자가 아니라, **스타일은 BananaX에서 고르고 문장 뼈대는 여기서 보강하는 보조 창고**로 쓰는 게 좋다.

### 4) 특집 아카이브에서 비교 감각을 익힌다

겨울 올림픽 아카이브는 그냥 이벤트 페이지가 아니다. 특정 주제를 오래 붙잡고 디자인 비교 기록을 남긴다는 점에서 오히려 더 배울 게 많다.

이런 특집 페이지를 보면 알 수 있다.

- 같은 주제라도 나라별로 톤이 달라질 수 있다
- 이벤트형 디자인은 반복 비교가 중요하다
- 아카이브가 남으면 나중에 레퍼런스로 다시 꺼내 쓰기 좋다

즉 이 페이지는 “한 번 보고 끝나는 홍보물”보다 **테마형 디자인 연구 노트**처럼 보는 편이 더 맞다.

## 그래서 실제로 어떻게 써먹으면 좋을까

이 사이트는 구경만 하면 아깝고, 아래처럼 붙여야 진가가 나온다.

### 사례 1) 수업용 요약 자료를 더 읽기 쉽게 만들기

NotebookLM이나 Gemini로 만든 수업 요약 자료가 너무 딱딱할 때, BananaX 메인 허브에서 먼저 인포그래픽 스타일을 고른다. 그다음 사례 갤러리에서 `Challenge → Points → Results`처럼 정보 구조를 흉내 내면 훨씬 읽기 쉬워진다.

핵심은 “내용을 다시 쓰는 것”보다 **보여주는 구조를 먼저 바꾸는 것**이다.

### 사례 2) 블로그 글을 카드뉴스로 옮길 때

블로그 글은 길고, 카드뉴스는 짧다. 이때 메인 허브에서 시각 스타일을 고르고, BananaPrompt에서 짧은 문장 패턴을 보강하면 변환 속도가 빨라진다.

특히 긴 글을 바로 이미지로 만들려 하지 말고,

1. 글에서 핵심 문장 4~6개를 뽑고
2. BananaPrompt로 문장을 더 짧게 다듬고
3. BananaX 스타일 프롬프트에 넣는 순서

로 가면 훨씬 덜 무너진다.

### 사례 3) 회의자료 첫 장에 들어갈 설명 이미지를 만들기

사내 보고서나 제안서 첫 장은 보통 텍스트가 많아지기 쉽다. 이럴 때 BananaX의 역할은 멋진 그림을 만드는 게 아니라, **복잡한 설명을 한 장 구조로 바꿔보는 실험 도구**가 된다.

예를 들면

- 배경
- 문제
- 해결 아이디어
- 기대 효과

처럼 4칸 구조를 먼저 만들고, 여기에 맞는 스타일을 고르면 보고서 첫 장의 밀도가 정리된다.

### 사례 4) 디자인 감이 없는 사람이 결과 품질을 끌어올릴 때

이 사이트의 가장 현실적인 장점은, 디자인을 잘 모르는 사람도 “무엇을 비교해야 하는지”부터 배울 수 있다는 점이다.

그냥 생성 버튼만 누르면 매번 운에 기대게 되는데, BananaX를 끼우면 적어도

- 어떤 스타일이 더 정보형인가
- 어떤 톤이 더 교육자료형인가
- 어떤 구조가 발표자료와 맞는가

를 비교하면서 고를 수 있다.

즉 결과를 잘 만드는 도구라기보다, **결과를 덜 감으로 고르게 만드는 도구**다.

## BananaX가 특히 잘하는 것

이번에 보며 가장 인상적이었던 건 아래 네 가지였다.

1. 처음 방문한 사람도 어디서 시작할지 알기 쉽게 `디렉터리형 허브`를 만들어뒀다.
2. 프롬프트만 던져주는 게 아니라 사례 갤러리와 연결해서 결과 감각을 익히게 한다.
3. 브라우저 안에만 API 키를 저장하고 서버에는 보내지 않는다고 명시해, 실험 장벽을 낮췄다.
4. 언어를 여러 개 지원해, 일본어권 내부 프로젝트에 머물지 않고 확장하려는 의도가 보인다.

## 아쉬운 점도 있다

좋은 사이트지만, 처음 쓰는 사람 기준으로 아쉬운 점도 분명하다.

> BananaX는 친절한 편이지만, 여전히 “이걸 어떤 입력값과 같이 써야 제일 잘 먹는지”까지는 사용자가 직접 익혀야 한다.

예를 들어 스타일 프롬프트를 복사했다고 해서 곧바로 좋은 결과가 나오지는 않는다. 결국 입력 원문이 너무 길거나, 정보 구조가 정리되지 않았거나, 시각화 대상이 불분명하면 결과는 흔들린다.

그래서 이 사이트를 만능 생성기로 기대하면 실망할 수 있다. 대신 **좋은 비교 기준과 빠른 출발점을 주는 도구**로 보면 만족도가 높다.

## 실제로 한 것

1. BananaX 공식 디렉터리에서 4개 사이트의 역할 분리를 먼저 읽었다.
2. 메인 허브, 사례 갤러리, BananaPrompt, 겨울 올림픽 아카이브를 각각 비교해 어떤 상황에서 써야 하는지 다시 묶었다.
3. GitHub 프로필 설명까지 함께 보며 이 프로젝트가 단발성 이미지 사이트가 아니라 `AI 도선 설계` 관점에서 만들어졌다는 점을 확인했다.

## 남겨둘 판단

BananaX를 깊게 보고 나서 가장 분명하게 남은 건, 이 사이트가 인포그래픽을 자동으로 뚝딱 만들어주는 마법 상자라기보다 **초보자가 AI 시각화에서 길을 잃지 않게 해주는 안내 체계**라는 점이었다.

그래서 이 도구를 가장 잘 쓰는 방법은 “멋진 프롬프트 하나 찾기”가 아니다.  
메인 허브에서 스타일을 고르고, 사례 갤러리에서 결과 구조를 익히고, BananaPrompt로 문장을 다듬고, 필요하면 특집 아카이브까지 참고하는 식으로 **사이트 전체를 하나의 작업 흐름처럼 쓰는 것**이 훨씬 강하다.
